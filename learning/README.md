# Learning

## If you are new

1. Read [`how-we-work.md`](../how-we-work.md). Ten minutes.
2. Read the [reference model](../reference-model/). Twenty minutes. Don't memorise it; you'll learn it by building.
3. Open the current assignment in [`assignments/`](../assignments/). That's where you learn.

Doctrine is issued at the point of need, scoped to the question it answers — not as a reading list. You will not be handed master documents before you've built anything.

## Reading, by tier

**Tier 1 — primary sources.** Vendor documentation, peer-reviewed papers, published incident reports. Citable.

| Source | Why |
|---|---|
| Vertex AI — *Evaluate Gen AI agents* | Native trajectory and final-response evals on GCP |
| Amazon Bedrock AgentCore — *Evaluations* | Native evaluators, OTEL traces, on AWS |
| Microsoft Foundry — *Agent evaluators* | Native agent evaluators on Azure |
| tau2-bench (Barres et al., 2025) | The benchmark used in E-01 |

**Tier 2 — orientation.** Good for getting the shape of a topic. Not citable where a Tier 1 source exists.

| Source | Why |
|---|---|
| *The Most Important Skill for AI Engineers: Evals Explained* + starter kit (aishwaryanr/awesome-generative-ai-guide) | The five-step eval method used in E-01 |
| *AI Engineer Projects That Get You Hired* (same repo) | Project 5 is the origin of E-01 |
